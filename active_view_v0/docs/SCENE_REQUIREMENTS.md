# ActiveView 场景要求

每次新增或改动场景，先读本文、[场景工作流](SCENE_WORKFLOW.md) 和相应的 `config/brief.yaml`。
本文规定实验口径和发布门槛；工作流规定目录、命令和可复现记录。

## 1. 选址与几何

- 一批场景先画总览和局部图，获得确认后再写配置。每条记录 Town、路口 ID、世界坐标、前后轮到哪批车，以及 Ego、Car2、RSU、UAV 的位置与方向。
- 按道路拓扑和补盲机制区分场景。同一路口换 seed、镜像方向、天气、车距或灯相，通常属于同一家族。可覆盖支路、道路转向、连续路口、主辅路进出、并道、分流和立体交叉。只使用实际地图支持的车道和连接。
- 用 OpenDRIVE 有向车道核验起点、接续、行驶方向和路线长度。不能以俯视重叠推断同层或可通行；立交分层可视化和统计，检查冻结检测器是否适配该处坡度和高度。
- RSU 放在明确服务路口的路侧杆位，优先选路口人行道外缘或路缘外的设施带，底座避开机动车道、停车带和人行道通行区域。用车道几何核对平面落点和同层路面标高，再用 CARLA 实景预览确认树冠、建筑和坡体不会挡住要观测的进口道。不能只用路口中心加统一横向偏移来确定杆位。记录服务路口 ID、杆底位置和传感器高度。
- RSU 与 UAV 的初始服务区默认对应不同路口；分别记录路口 ID，并检查 RSU 实际杆位和 UAV 初始点、网格中心是否仍对应各自路口。允许感知范围重叠，以便融合和交接。若场景只有一个服务路口，须在 brief 中解释两者分别服务的区域和共址原因。
- 划分训练、验证、测试时，相邻或重叠路段及同一家族的天气、灯相、seed 变体保持同一划分。Town04 首批用同一个 split group，待按实际路线审阅后再考虑细分。

## 2. 交通与两批目标

- 2 辆感知车（Ego、Car2）、1 RSU、1 逻辑 UAV。Ego 和 Car2 都沿合法路线正常行驶；检查实际转向、通过路口、驶出覆盖区和连续停驶时间。允许合法等灯；不能用闯灯、强制移动、静止重复目标或中途瞬移通过验收。
- 每条先写能被证伪的 A、B 两段假设：早段谁看不到什么、换班触发是什么、后段有哪些新车、为何不用一直停在一个好点。至少有两组真实进出或切换可见性的车；可利用行进大车、视野边缘、转角、桥体和 Car2 离开。也应保留无需移动的时段和效果不明显的对照。
- 默认试验 60 秒、600 帧、10 Hz。以 Where2comm 现有 Ego ROI（纵 ±140.8 m、横 ±40 m）和实际类别、高度过滤后的 GT 统计；排除感知车。期望中位 16–22 辆，至少 80% 帧在 12–25 辆。遮挡、密度和目标换批均要看逐帧实测。记录 moving GT、进出 ROI 的 ID，并检查同一辆车重复帧。
- 单组有多个可补 ID，后段至少 3 个未在前段被补到的 ID。这里“可补”指加入 UAV 后产生 Ego+Car2+RSU 原本漏掉的 TP；同一固定阈值与同一 GT 匹配口径。用固定路网运动估算出来的 ROI 数、车流角色计数和 LiDAR 射程均不能代替实测可补 ID。

## 3. 视点与公平比较

- 沿用默认 80 m LiDAR、40 m UAV 相对参考地面高度、5×5 / 15 m 网格、1 Hz 决策及 15 m/s 上限；默认中心点初始。指定 A/B 两候选和限速可达路径，事件窗口应留出到达后的有效观测时间。只在同一车流和传感器条件下换机位。
- 沿用 Town05 的 Where2comm 输入与 GT 裁剪范围 `[-140.8, -40.0, -3.0, 140.8, 40.0, 1.0]`（Ego 坐标，米），运行前核对 checkpoint 配置。`z_max=+1.0 m` 是检测裁剪上界，与传感器物理射程和 UAV 飞行高度不同。
- 主对比为 `center_fixed`。同时报告预登记固定点、伴飞、巡逻，以及用全序列选出的 `detector_best_fixed` 诊断值。用两段逐点结果检查 A/B 优势是否互换。速度受限 oracle 只估计离线机会；真正的在线策略不读未来帧、GT 或旁边的候选点云。
- 报告 AP50、R50、按目标 ID 的漏检恢复，完整片段和预先界定的事件窗均报告。用同一 GT 和检测器安排各策略。在验证集确定筛选标准，不因测试集涨点好才保留片段。

### Town05 试验经验：先确认盲区会换位置

| 场景 | 限速 oracle 相对中心悬停 AP50 | 最佳固定点相对中心 | 限速 oracle 相对最佳固定点 |
| --- | ---: | ---: | ---: |
| `scene_0024` | +7.30 pp | +3.65 pp | +3.65 pp |
| `scene_0025` | +9.39 pp | +7.59 pp | +1.80 pp |
| `scene_0026` | +5.64 pp | +1.13 pp | +4.51 pp |

- **遮挡的是 Ego 要检测的目标。** 车身、道路转角等挡住 Ego 到目标的视线时，先查 Car2 和 RSU 能否补上；还要查初始悬停点是否已经能看到后段。因此为 A/B 分别记目标路线、遮挡物和预计开始/结束时间，并标清各感知代理服务哪条进口道。优先选后段成批出现的新目标，让转场的收益有机会持续；不能只看中心到目标的距离或单帧遮挡。
- **让 A 与 B 各有真正擅长的时段。** 中心初始机位应能服务早段 A，且放在合理道路上空。B 可用相邻进口道、转弯后的同层车流、驶离视野后的新车队来形成；RSU 与 Car2 继续正常承担协同任务。用限速路程估算需要提前多久起飞，验证到达后还有足够的目标留存；若只够抢到一两帧，或一个固定点能覆盖全程，按对照解释。只在连续空间里可达的方案单列实机验证。
- **区分换到好位置和持续换位。** 主表同时列 `限速 oracle − center_fixed`、`best_fixed − center_fixed`、`限速 oracle − best_fixed`。固定点由整段数据事后选出，仅供诊断；可部署对照应使用同起点、速度和时间预算，加入只依据已见观测执行一次迁移后悬停的策略，再与多次调整比较。单次迁移有收益仍然有效；能超越单次迁移才支持持续调整的价值。
- **用配对场景检验机制。** 同一路线安排大车与轿车遮挡对照、B 分批持续到达与短时到达对照，或 Car2 留在 B 与正常驶离对照；每对尽量只改一个因素。按 A/B 窗逐帧核对 Ego/地面融合、初始悬停和移动结果及新补检 ID；全段额外报告 AP50/R50。`+7–8 pp AP50` 作为开发期目标和分层观察指标，保留阴性对照，提前锁定测试划分。Town05 的这些增益是离线限速 oracle 结果，不能归因给某一项改动，也不等价于在线策略成绩。

### Town06 试验经验：用连续进口做补盲交接

**证据范围。** Town06 批次 `grid_60s/20261128_001552` 的合并报告包含 14 个场景，`scene_0009` 缺报告。每个已报告场景 600 帧、25 个候选机位，均通过 checkpoint transfer sanity；14/14 在相对 `detector_best_fixed` 的 AP50 和 R50 上同时提升至少 1 个百分点（`ACTIVE_VIEW_SIGNAL`）。下表是对已报告场景等权平均的 class-agnostic BEV 指标，不是把所有预测合并后重新计算的 AP。离线 oracle 用到 GT；本批结果不作为在线策略成绩，也不能推断缺失场景表现。

| 策略 | AP50 | R50 |
| --- | ---: | ---: |
| 地面融合（Ego + Car2 + RSU） | 17.58 | 23.04 |
| 中心悬停 | 28.67 | 32.80 |
| 事后最佳固定点 | 33.79 | 37.44 |
| 伴飞 | 33.63 | 37.15 |
| 巡逻 | 28.10 | 32.36 |
| 限速离线 oracle | 37.71 | 41.25 |
| 不限速逐帧 oracle | 40.90 | 44.28 |

限速 oracle 平均比中心悬停高 **+9.03 / +8.45 pp（AP50/R50）**，比最佳固定点高 **+3.92 / +3.81 pp**，比伴飞高 **+4.08 / +4.10 pp**。其平均路径长 456.4 m，长于伴飞（110.3 m）。比较策略须同时给出移动距离、时间和能耗代理；高检测分数本身不能说明更高效率。逐帧 oracle 平均路径长约 7.25 km，仅用来诊断机位机会与限速损失。

#### 选路线和放机位

- **优先画出两段可到达的视角交接，再选车速和到达时间。** `0007/0008` 的 J1050→J1203 匝道、`0011` 的 J332→J268 连续汇合、`0010` 的反向通道，限速 oracle 的 AP50 分别比最佳固定点高 +7.40、+7.95、+9.09、+5.98 pp。可优先尝试这些几何关系：早段从近侧进口看到 A；后段新目标从另一侧进入 Ego ROI；移动后能持续补到多个新 ID。逐帧记录 A/B 的真实来车方向、入区时刻、离区时刻、检测缺口，以及机位优势是否真的互换；场景总分本身不能证明发生过哪一种交接。
- **先给飞行留时间，再调整 B 组到达。** 对每个机位分别记录世界坐标、地面目标参考点、斜距、同层关系、从 A 出发的合法路径和最早到达时间。以 `0007` 为例，A 名义窗为 6–13 s，B 为 16–29 s，格点最短路径 4 步；若 A 结束才离开，理想情况下约在 17 s 到达，B 开头不能计作移动机位上的观测。若要求实时，另外扣掉观测、推理及动作生效延迟。80 m 是斜距；平地相对高 40 m 时，纯几何水平射程约 69 m，实际还受遮挡和点云密度影响。网格内外是两个评估支撑域：`0015` 已有报告只说明 25 点网格内的收益，`continuous_extension` 要单独跑才有结果。
- **让 Car2 真正参与地面协同。** Town06 从草案修订时，`0001/0002`、`0005/0006`、`0007/0008` 让 Car2 同向从 Ego 后方约 28–32 m 出发；名义 ROI 和 80 m 斜距重叠时间分别由 0、0、17.5 s 提到 60 s。后续场景记录分段重叠时长、跟车进度、实际 Car2/RSU 命中和地面融合漏检，不用名义重叠代表可见性。若要研究 Car2 驶离，像 `0003/0004` 那样同起点、同速、同一路口再分流，基础车流保持一致。单条场景不靠让 Car2 或 RSU 退出观测来放大 UAV 收益。

#### 用配对和对照解释分数

- **大车、流量和时序都需要验证，不能凭脚本假定有效。** `0001/0002` 的车型对照中，厢式车版本相对最佳固定点的 AP50 增益较大（+3.56 vs +1.60 pp），但绝对 AP50 低于轿车版本（39.68 vs 46.75）。`0005/0006` 改 B 分批与集中到达，相对中心悬停的 AP50 增益均为 +6.42 pp；`0007/0008` 改一辆 B 车走匝道还是主线，两场景仍都明显优于事后最佳固定点。按同一配对的实际 A/B 轨迹、漏检位置、补回目标 ID、重复种子和逐窗分数解释机制，不根据单次全段结果断言某个干预有因果效果。
- **检查是否只需要一次换位。** `0014` 相对中心悬停 AP50 提升 +11.89 pp，但相对最佳固定点只有 +1.41 pp，伴飞 AP50 为 39.33、已接近最佳固定点 39.22；`0013` 绝对 AP50 高（64.92），相对最佳固定点仍只多 +3.12 pp。这类场景保留用于对比：中心悬停 → 预登记固定机位 → 同起点、同限速、只用已见数据迁移一次后悬停 → 持续调整。至少按 AP50/R50、路径长和新补回的目标 ID 共同报告。
- **保留弱收益和缺失项。** `0012`、`0015` 的限速 AP50 分别为 12.11、14.32，相对最佳固定点仅 +1.12、+1.89 pp；它们虽达判据，仍应单列排查地面检测难度、晚到车流、有限网格和检测器域差。缺报告的开阔并流对照 `0009` 先核对采集文件和评估日志、补跑报告，再纳入统计。不能因缺报告或涨点小临时改测试名单；六城训练时保持路线家族和配对场景的划分，并冻结用于比较移动策略的检测 checkpoint。

## 4. 验证顺序与发布

1. **离线预检：** `activeview validate`、路网版本、合法车道和转接、初始间距、路线余量、固定布局、时间步和坐标。按车道和名义速度做密度预算，明显不够时先改车流再实跑。离线预检不是 CARLA 验收。
2. **实机预览：** 用目标 CARLA 资产预览起止、转弯和 A/B 两窗口，查实际灯态、生成车数量和车道行为；先用每种道路类型的一条检查最容易失败的设计。
3. **完整预采：** `activeview run --mode offline_hover`，再 `activeview check-run`；确认帧数、GT、实际移动及过路口，做同有效 config 重放比较。有传感器、相位、路线或密度故障就修正，再验证。
4. **主动补盲验收：** 采 25 点，同帧运行 Where2comm，先冒烟、再完整评测。检查 A/B 漏检恢复与限速路径，并单列 `best_fixed`。没达到活动判据的样本可列为对照，不把离线估计标作检测结果。
5. **确认后发布：** 将通过的 `scene.yaml`、`brief.yaml` 和轻量验证说明写入 `active_view_v0/scenes/<Town>/<scene_id>/config/` 及已有项目分支。标明地图版本、流量种子、真实失败项和 checkpoint；实机验收的空缺在补齐前保持候选状态。

## 参考依据

- [AirV2X, §3](https://arxiv.org/html/2506.19283v3)：参考城市场景和非城市交通多样性、固定地面代理与无人机，以及悬停、巡逻、伴飞基线。本项目单独定义补盲目标换班和 UAV 决策测试。
- [Griffin, §3](https://arxiv.org/html/2503.06983v2)：参考交通流、相对位置、实例可见性、连续 ID 和同步采集。Griffin 的 UAV 是相机；本项目的 UAV LiDAR、60 秒时长和 25 点网格有自己的实验口径。
